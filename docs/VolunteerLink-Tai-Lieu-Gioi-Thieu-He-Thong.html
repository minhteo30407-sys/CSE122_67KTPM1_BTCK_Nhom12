HỆ THỐNG TÌNH NGUYỆN VIÊN VOLUNTEERLINK

BTL-24 · Học phần Phát triển ứng dụng web cơ bản (CSE122)
Nhóm phát triển (2 thành viên): Trần Văn Minh & Nguyễn Bá Thành
Mục tiêu sản phẩm: VolunteerLink là ứng dụng web frontend nguyên mẫu, chuyên biệt kết nối tình nguyện viên với các hoạt động thiện nguyện cộng đồng. Hệ thống giải quyết 4 bài toán cấp thiết: (1) Thông tin phân tán, (2) Khó ghép đúng kỹ năng chuyên môn, (3) Điều phối ca trực thủ công, (4) Khó khăn trong việc ghi nhận và tổng kết đóng góp xã hội.

1. Kiến trúc & Công nghệ nền tảng

  • HTML5 Semantic: Chuẩn hóa ngữ nghĩa (header, nav, aside, main, section, article, form, footer).
  • CSS3 thuần (Pure CSS): Sử dụng CSS Variables (Design Tokens), Flexbox và CSS Grid. Thiết kế tối giản, sạch sẽ, không phụ thuộc framework bên thứ ba (như Bootstrap). Hỗ trợ responsive hoàn chỉnh cho Desktop, Tablet và Mobile.
  • JavaScript thuần (Vanilla ES6+): Lập trình DOM, xử lý sự kiện, kiểm tra tính hợp lệ biểu mẫu (Form validation), quản trị trạng thái (loading, rỗng, lỗi, thành công).
  • Lưu trữ dữ liệu giả lập (Data Layer): Kết hợp 6 thực thể JSON (`volunteers`, `organizations`, `opportunities`, `shifts`, `registrations`, `skills`) được tự động đồng bộ vào LocalStorage của trình duyệt, hỗ trợ đầy đủ các thao tác CRUD.
  • Tổ chức mã nguồn: Tích hợp 19 màn hình vào dist/; toàn bộ trang HTML, CSS, JavaScript và dữ liệu mẫu được tập trung tại đây để dễ chạy và bảo trì.

4. Thiết kế & Trải nghiệm các tính năng AI

Nguyên tắc trải nghiệm AI phân tích (AI UX Flow)

Ba công cụ phân tích dùng quy trình 6 bước; chatbot có giao diện hội thoại riêng, trạng thái chờ và thông báo lỗi rõ ràng:
  1. Nhập dữ liệu (Input): Người dùng chọn đối tượng cần phân tích (ca trực, hoạt động, tiêu chí).
  2. Kiểm tra hợp lệ (Validate): Hệ thống đảm bảo đủ dữ liệu đầu vào trước khi kích hoạt.
  3. Đang xử lý (Loading/Spinner): Hiệu ứng đang phân tích dữ liệu, thông báo trạng thái rõ ràng.
  4. Kết quả (Result): Hiển thị kết quả được xếp hạng và gắn nhãn điểm số minh bạch.
  5. Giải thích lý do (Explain - "Vì sao có kết quả này?"): Khối phân tích chi tiết tiêu chí logic phía sau đề xuất.
  6. Quyền kiểm soát (User Control): Bộ 4 hành động: Chấp nhận / Chỉnh sửa / Từ chối / Tạo lại; kèm trạng thái lỗi khi thiếu dữ liệu và tùy chọn Làm thủ công.

5. Hướng dẫn chạy thử nghiệm & Chấm điểm (Quick Start)

  1. Cấu hình chatbot: Sao chép .env.example thành .env ở thư mục gốc và điền API key Google Gemini vào GEMINI_API_KEY. Không đưa API key lên GitHub.
